# 长页文字处理响应性

本轮优化保留图块尺寸、预渲染范围、图片缓存预算和高清完成条件。主要变化是复用页面
布局，以及将长页文字结构化计算移出 UI isolate，阅读和搜索共享一次提取结果。

## 测量方法

2026-09-21，在 macOS arm64 的 `flutter test` 环境运行。使用仓库已有的
800 × 40000pt 文字长页（原始文字 141591 字符），以及 `multipage40.pdf` 的第一页。
原路径使用 `page.loadStructuredText()`，新路径使用 `loadStructuredPageText()`。
每条路径预热一次，交替顺序测量五轮，每轮重新打开 PDF，打开时间不计入结果。

测量从原生文字提取到结构化结果返回的总时间；同时用 1ms 周期定时器观察调用方
isolate 的最长事件循环间隔。表中是五轮中位数。定时器会受系统调度、GC 和数据传输
影响，不能将该指标直接当作 UI 帧耗时、掉帧数量或 Release FPS。

## 结果

| 样本 | 路径 | 文字就绪总时间 ms | 最长事件循环间隔 ms |
|---|---|---:|---:|
| 长文字页 | 原算法原位置执行 | 75.586 | 39.103 |
| 长文字页 | 后台结构化 | 101.450 | 12.806 |
| 普通 PDF 第一页 | 原算法原位置执行 | 0.328 | 2.320 |
| 普通 PDF 第一页 | 新路径，短页就地处理 | 0.353 | 2.345 |

长页的事件循环最长间隔下降，但首次文字就绪时间增加约 26ms。首次选择或搜索可能
因此略晚就绪；高清显示不等待文字完成。原生文字提取仍在 PDFium 原有 worker 上，
后台结构化不会占用该 worker，但启动 isolate、传递原始文字坐标和 GC 仍有成本。
本次使用 8192 字符作为后台处理阈值，避免给普通短页加入 isolate 启动成本。

这验证的是冷文字缓存时的改进。文字已经缓存后的持续滚动，仍应另测图块排队、
生成速度及真机帧耗时。下一阶段改变预加载/淘汰/图块策略之前，应分别测量 A4 和
流式的连续滚动、反向滚动、远距离跳转及缩放。

布局计数回归使用 1000 页合成文档：60 帧纯平移从 60 次全量布局降为 0 次；
单张长页同样复用布局。计数没有覆盖所有逐页遍历，也不是帧率提升百分比。

## 复现

```sh
cd ui
SGV_TEXT_BENCH_OUTPUT=/tmp/sgv-text-loading-results.json \
  flutter test --no-pub benchmark/text_loading_benchmark_test.dart
flutter test --no-pub test/page_text_cache_test.dart test/viewer_layout_cache_test.dart
```

基准输出包含各轮原始数据与汇总，不设容易受机器负载影响的耗时通过阈值。
正确性由回归测试保证：文字、字符矩形和片段方向与原算法一致；共享在途任务；
页面/文档替换后旧结果无法回填；文字未就绪时图片仍可报告高清完成。
